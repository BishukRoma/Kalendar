## 1. Архитектура продукта и роли

### Роли пользователей
- **Администратор** — полный доступ, управление feature-flags, настройка биллинга
- **Менеджер** — управление бронями, объектами, клиентами
- **Горничная** — отдельный Telegram-бот + открытая страница с расписанием уборок
- **Собственник** — отдельная роль (в разработке), видит только свои объекты

### Feature Flags
Система постепенного включения фич через CarrotQuest (сейчас заменяется).
**Порядок запуска новой функции:**
1. Feature-flag на проде → выкатка под флагом
2. Черновое видео → чистовое видео → проверка
3. Тестовая группа клиентов (таблица ID юзера + ID агентства)
4. Видео в CQ + включение флага тестовой группе
5. Сбор ОС через аккаунт-менеджеров
6. Анализ + доработки → глобальный rollout

## 2. Шахматка — механика создания брони

Детальная механика попапа создания брони:
1. Открывается попап
2. Сразу летит запрос: `preparing=true` (без валидаций) — сохраняет черновик брони
3. Возвращается черновик с ID
4. Пользователь настраивает платежи, залоги, остальные атрибуты
5. «Сохранить» → валидации → закрытие попапа при успехе

**Платежи в брони:**
- Можно редактировать только счёт и комментарий платежа
- Возврат: поля неактивны до выбора платежа; сумма + штраф = полная сумма платежа
- Залог — только один на бронь; кнопка «добавить ещё» скрывается
- Залог нельзя редактировать после создания

**Настройки «Прием платежей»:**
- Нет активных платёжных систем → форма заблокирована
- Нет Монеты → инфо-нотификатор
- Отключение Монеты → «предоплату считать залогом» = false автоматически

## 3. Залог (Возвращаемая предоплата)

**Проблема:** При взятии залога через Монету комиссия падает на арендодателя — крупные клиенты не готовы.

**Решение:** Переложить комиссию на гостя.

**Сценарий:**
- Стоимость: 2 ночи × 1000 руб. = 2000 руб.
- Залог (возвращается после выезда): 1000 руб.
- К оплате сейчас: 1000 руб.
- Остаток: доплатить на месте

**Гипотезы возражений:**
- Гость удивится, что залог вернули не в полном объёме (вычли комиссию)
- Путаница при заселении: гость думает 1000 = остаток за жильё + залог

## 4. Channel Manager — типы подключений

**Цель редизайна:** Снять нагрузку с техподдержки, сделать подключение самостоятельным.

### Тип 1: iCalendar
- Обмен ссылками: наша ссылка → на площадку; ссылка площадки → к нам
- Наша ссылка одна для объекта (подходит для любых iCal-площадок)
- **Ограничения:** синхронизация раз в час; только занятость, БЕЗ цен и минимальных сроков
- Поэтому для iCal не нужен выбор наценки и валюты

### Тип 2: Один экран (упрощённое подключение)
Пользователь вводит:
- ID объекта на площадке
- Наценку
- Валюту (не всегда)

### Тип 3: По шагам (для отельных площадок)
1. Выбор отеля
2. Выбор категории номеров
3. Настройка тарифов (наценка руб/валюта, от базовой цены RC или от другого тарифа, мин/макс дней, закрыт ли по умолчанию)
4. Настройки наценок на кол-во гостей

### Тип 4: Аккаунт + объекты (самый сложный)
Сначала подключается аккаунт, потом объекты.

**Avito — схема:**
1. Пользователь вводит ID аккаунта Avito
2. RealtyCalendar раз в сутки автоматически отправляет письма в Avito
3. Avito отвечает `client_id` и `client_secret` → прописывается в аккаунте
4. Можно добавить несколько аккаунтов Avito

**Airbnb** — была аналогичная схема, сейчас не работает (закрыли API). Планируется иностранный прокси-провайдер.

### Что показывать по каждой интеграции
- Внешний ID
- Статус: Активно / Не активно / Ошибки
- Наценка (общая или по тарифам)

## 5. MiniCRM — дополнительный модуль

**Назначение:** Упрощение работы менеджера и взаимодействие с гостями.

### Функции
**Первичная настройка:**
- Объекты подтягиваются из RC автоматически
- К каждому объекту: описание (Wi-Fi, замок, мусор, советы), доп. услуги
- Горничные: назначение на объекты, стоимость уборки

**Гостевая страница (уникальная ссылка):**
- Даты и время заезда
- Сколько оплачено, сумма залога
- Карта с маршрутом
- Описания объекта по темам
- Заказ доп. услуг
- Код от ключницы (в день заезда)
- Указание времени заезда/выезда
- Оценка чистоты

**Единая доска менеджера:**
- Текущие гости
- Гости, прибывающие сегодня / завтра / позже
- Кому нужно получить паспорт / залог / оплату
- Платежи из RC подтягиваются автоматически
- Из карточки: открыть бронь в RC, WhatsApp, страницу гостя

**Уборки:**
- Автосоздание задачи на уборку в день выезда
- Если одна горничная — назначается автоматически; если несколько — менеджер выбирает
- Показывается период уборки (когда выезд текущего / когда заезд следующего)
- Горничная: открытая страница с расписанием + Telegram-бот с уведомлениями
- Статус квартиры: убрана / не убрана / уборка начата
- Стоимость уборки → в расходы RC

## 7. MVP для ЦИАН — детальная интеграция

**Механика:**
1. Кнопка «Забронировать» на странице объявления ЦИАН
2. Ссылка ведёт на `cian.realtycalendar.ru/...`

**Параметры от ЦИАН:**
- `id` объекта на стороне ЦИАН
- Дата заезда, дата выезда
- Кол-во гостей
- `uid` — уникальный идентификатор запроса

**Страница бронирования:**
- Цена за сутки и общая стоимость рассчитываются в реальном времени
- Email гостя (обязателен)
- Оплата через Монету: Карта/СБП гостя → Монета → СБП хоста
- Деньги поступают хосту на следующий день после заезда
- Комиссия 3.5% + 40 руб. на хосте + 15% от суммы на хосте

**Оповещения:**
- Хосту: почта + колокольчик + веб-пуш + мобильный-пуш
- Гостю: вебхук от RC → ЦИАН отправляет сам
- Retry вебхука: 6 раз с интервалом 10 минут при не-200

**Отмена:**
- С возвратом денег / без возврата денег
- Админка со списком бронирований ЦИАН

## 10. Технические инсайты из Notion

### Платёжная система «Монета»
- Собственный платёжный процессинг
- Поддержка: Карта, СБП
- Комиссия 3.5% + 40 руб. (для ЦИАН — на хосте)
- Холдирование средств
- Залоги через Монету

### iCal — ограничения
- Синхронизация **раз в час** (не в реальном времени)
- Только занятость, **без цен и минимальных сроков**
- Это главная причина овербукинга при iCal-only интеграции

### Ключевые причины нагрузки на поддержку
- Подключение площадок требовало участия тех. поддержки
- Разнородный UI Channel Manager (сделан программистами, не дизайнерами)
- Пользователи не могли самостоятельно разобраться с интеграциями

### ИИ-направления (Внедрение ИИ)
- Речевая аналитика / контроль качества звонков
- Резюме встреч и звонков (Whisper)
- Классификация обращений по тексту
- Поиск ответов по базе знаний
- Автоматические ответы на тикеты

## 11. Инсайты для нашего продукта

### Что критично взять у RC
- Механика `preparing=true` при создании брони (сначала сохраняем черновик, потом валидируем)
- Типизация Channel Manager (4 типа подключений) — применить сразу правильно
- Список платформ и их типы — приоритизировать по объёму рынка РФ
- Один залог на бронь — жёсткое правило

### Что сделать лучше RC
- iCal синхронизируется **раз в час** → у нас будет доп. мгновенная блокировка через Redis lock при любой брони
- Расходы (постоянные/переменные) — RC это не умеет, наше конкурентное преимущество
- Аналитика по реальной прибыли, а не только выручке
- Самостоятельное подключение каналов без техподдержки (RC это только делает, мы строим правильно с нуля)

### Платформы для MVP (по приоритету рынка РФ)
**P1 (обязательно):** Avito, Ostrovok, CIAN, iCal (Airbnb)
**P2:** Sutochno, Tvil, Bronevik, OneTwoTrip, Expedia
**P3:** Все остальные (один экран — дёшево подключить)
